# NVL-AWG-03 — Backend-aware Standby and guarded Quick Switch

**Status:** repository-only change. Does not deploy to Core or alter existing serving Edges, DNS, customer accounts, or network configuration.

## What changes

- Manual Edge Wizard uses a dedicated, read-only AWG verification before and after an AWG new-Edge installation and again before marking `EDGE_READY` as `STANDBY`. The previous WG path remains unchanged.
- The AWG verifier reads an explicit `VERIFIED` binding from `edge_tunnel_bindings`, matches exactly one manual journal SSH pin, checks Core AWG peer ownership and Core→Edge path, connects to the Edge with that pinned host key, checks the reverse peer/AllowedIPs, the Edge interface /32 and live + persisted SSH/TLS DNAT, SNAT, forwarding, and reboot enablement.
- Journal performs a second backend/registry verification in the same SQLite transaction that changes the Edge role to STANDBY. A wrong/missing backend cannot be promoted.
- Manual Quick Switch dispatches on the **target's registered backend**. Legacy WG keeps the existing `check_manual_relay_via_cz04b`. AWG requires a fresh pinned target verification before DNS and during every recovery/DB commit, plus a separate short-lived runtime limiter gate.
- Existing Quick Switch's exact DNS/account fingerprint, operator confirmation, journaled lock, rollback and 6G/K2 guards are retained.

## Safety gates

- `NVL_AWG_NEW_EDGE_ENABLED` defaults to OFF; AWG new-Edge UI stays hidden until explicitly enabled following a pinned release.
- `NVL_AWG_CUTOVER_ENABLED` defaults to OFF. Setting it to `1` **alone is never enough** to route AWG clients.
- AWG routing also requires a root-only, time-limited marker `/run/nvl-awg-limiter-ready`, containing exactly `NVL_AWG_LIMITER_READY <target-tunnel-/32-source-IP>`. This marker is **not generated by the bot or its Telegram callbacks**. The independent Core runtime limiter health reconciliation/witness writer is **not implemented in AWG-03**, so AWG customer cutover remains HOLD-only even if the source code is merged. Do not create this marker manually without an independently verified installed and running AWG-aware limiter.
- A fresh independent customer ISP NPV connection witness and matching DNS route metadata are still required by the existing Quick Switch controls. The currently serving AWG Edge is deliberately not auto-enrolled or hardcoded.
